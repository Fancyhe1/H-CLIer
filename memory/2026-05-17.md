# 2026-05-17 工作记录

## 对话摘要

今天主要完成了 **未读消息提示功能的噪音过滤优化**。用户反馈之前的实现会将 Claude 的思考过程、状态提示（如 "✻ Metamorphosing…"、"※ recap:…" 等）误判为新消息，触发未读提示。

### 关键决策

1. **放弃内容关键词过滤方案**
   - 原方案：通过检测特定字符（✻、※、recap 等）来过滤噪音
   - 问题：Claude 的思考过程符号一直在变化，无法通过固定关键词过滤
   - 用户反馈："开头的符号是一直在变化的"

2. **改用延迟标记策略**
   - 新方案：输出开始时不标记，等输出停止 3 秒后才标记未读
   - 原理：思考过程是连续输出，定时器不断被重置，永远不会触发
   - 只有 Claude 完成回答并停止输出 3 秒后才标记未读

### 技术实现

```typescript
// 延迟标记策略核心代码
let outputTimer: ReturnType<typeof setTimeout> | null = null
const unlisten = await listen<string>(`pty-output-${ptyId}`, (event) => {
  term.write(event.payload)
  
  const instance = terminalsRef.current.get(activeSessionId)
  if (instance && instance.shouldMarkUnread && event.payload) {
    // 每次收到输出都重置定时器
    if (outputTimer) {
      clearTimeout(outputTimer)
    }
    // 输出停止 3 秒后才标记未读
    outputTimer = setTimeout(() => {
      const currentInstance = terminalsRef.current.get(activeSessionId)
      if (currentInstance && currentInstance.shouldMarkUnread) {
        useSessionStore.getState().setHasUnread(activeSessionId, true)
      }
    }, 3000)
  }
})
```

### 技术教训

1. **内容过滤 vs 行为过滤**
   - 内容过滤需要维护关键词列表，容易失效
   - 行为过滤（如延迟标记）更稳定，不依赖具体内容格式

2. **React useEffect 依赖问题**
   - 之前因 `sessions` 依赖导致无限循环
   - 解决方案：使用 `setTimeout` 延迟执行状态更新

3. **闭包捕获问题**
   - PTY 监听器中的 `activeSessionId` 是闭包捕获的
   - 通过 `terminalsRef` 和 `shouldMarkUnread` 标志解决
